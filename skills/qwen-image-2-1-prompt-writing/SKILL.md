# Qwen Image 2.1 图像提示词

这是一份本项目编写的提示词方法包，通过通用 Skills 激活与生图提示词优化合同运行。它不要求工作流内运行提示词增强模型，也不负责调用图片生成、选择模型或修改工作台参数。

## 片段与素材边界

片段从完整剧集或用户当前稿件出发，可以包含一个或多个连续剪辑镜头。镜头只表达片段内部的叙事次序，不要求先创建场次、故事板、静帧或逐镜业务记录。时长、镜头数和参考图数量以用户意图及本次冻结能力为准，不固定秒数，不要求先生成六张或九张图片。

图片是普通素材。人物外观、环境、风格、整片首尾或片内镜头边界等用途来自本次明确绑定；不能根据节点名、图片排列或画面猜测首尾。无参考图的合法输入也能完成内容表达。环境描述不要求一个旧场景实体，也不把环境图当成视频首帧。

本包只提供创作方法，只使用本次实际提供且已获授权的工具，不自行注册或调用其它能力。是否生成图片或视频由本次授权与实际可用工具决定，文字任务只交稿。

## 输入与输出边界

- 以应用给出的用户原稿、生成模式、工作台参数及有序参考图为输入。用户明确的主体、数量、动作、配色、空间关系和文字必须保留。
- 有参考图时读实际图片及其绑定信息，不把文件名当成图像内容。不根据缺失或看不清的图片编造细节；所选模型无法读取图片时按应用合同报告限制。
- 无参考图的文生图采用下方画面描述方法；参考图编辑采用下方编辑指令方法。模式由输入合同决定，不因为输入简短而擅自切换。
- **外层输出严格遵守调用方提供的结构和字段闭集**。把最终提示词正文放入应用指定字段；不另加 `rewritten_prompt`、`wh_ratio`、解释、Markdown 围栏或备选版本。调用方只要求正文时，只返回正文。
- 画幅、分辨率、种子等由工作台控制，不输出新参数，也不把像素规格写进提示词。用户事实与冻结参数有冲突时按应用合同报告，不静默选一方。

## 文生图：描述已经完成的画面

1. 先整理用户固定的事实与开放的视觉细节，区分要画进画面的内容和对本次工作的要求。不得把“优化一下”“清晰输出”等操作指令写成画中元素。
2. 默认建议英文，应用冻结语言或用户本次要求优先；采用客观画面描述。开头交代媒介、风格、主体和背景，再按背景、主体、周边或版面区域的顺序展开，让位置关系清楚可定位。
3. 用具体的颜色层次、材料表面、动作姿态和光线方向表达视觉效果；仅在本次允许扩展时补充合理视觉细节服务原稿，不新增改变主题的人物、品牌、剧情或文字。
4. 用户指定要显示的文字逐字保留，使用直双引号标识，并说明它的位置、字号层级、颜色和排版。画内文字保持指定语言，不能因正文英文而翻译。没有文字需求时不增添标语和标签。
5. 单一场景通常写成连贯一段；本来就是分区版式时可以逐区描述。篇幅随信息量调整，不为凑字数重复和增添事实，不堆砌“8K”“杰作”等质量口号。
6. 结尾简洁交代整体构图与气氛。保持对象数量、遮挡、反射和阴影关系自洽。

## 图片编辑：明确改什么、保留什么

1. 以实际参考图为锚，先理解用户是在局部修改原图，还是用参考主体构建新画面。局部编辑只细化所要求的改动；重新布景或合成时，根据任务补足场景、光线和构图。
2. 明确目标对象、修改动作、目标状态及位置范围。只改变用户指定的属性，明确相关的身份、姿态、服装、背景或构图保留项；不得为了更丰富而重写整幅原图。
3. 编辑指令建议沿用用户语言，未指定时可用英文；本次冻结语言优先。描述语言与画内文字语言分别决定：用户给了确切文字或目标语言时优先遵守；否则沿用原图主要文字语言；原图无文字时采用用户指令语言。不要擅自生成双语标签。
4. 画面文字的新增、删除、替换要指出具体位置和目标文字；不误改其余文案。新文字用直双引号标识，并描述需要保留或改变的字体层级、对齐和色彩。
5. 单图编辑自然地称为“图像”或“输入图”，不使用多图标签。**多图时参考图编号从一开始，与应用输入数组及工作台提交顺序完全一致**：第一张为 `<image1>`，第二张为 `<image2>`，依此类推。原样使用应用给出的编号，不按内容重要性、文件名、角色或编辑叙述顺序重排。
6. 多图合成说明每张图提供什么，例如主体来自 `<image1>`、服装来自 `<image2>`。不得交换编号、虚构未提供的图片或把多张图含糊合并成“参考图”。
7. 保持执行指令简洁且具体。遇到用户未要求改变的模糊细节时要求保留，不猜测不可见的外观。

## 提交前检查

- 本次只优化提示词，输出不触发生图；应用将优化结果保存为新版本，原稿保留。不要要求覆盖或删除原稿。
- 输出字段符合本次调用的应用合同；正文没有再包裹另一层官方增强器 JSON。
- 用户固定事实和画内文字完整，引用的图片编号都来自输入，顺序一致；没有私自修改画幅或参考图集合。
- 若应用提供结构化问题或限制字段，按它的枚举和引用填写，不能自造字段或用自由文本代替要求的结构。

## 评审与交付

按本次请求给定的结构和字段闭集返回结果，不另造业务 JSON、编号、错误码或工具。程序只校验必要结构、输入闭集中的真实引用、真实目标能力、权限及数据安全。缺少输入时说明具体缺口，不编造素材、来源或身份，不静默切模型或输入模式。

写作顺序、标签、模板、表达语言建议、画面质量与语义保真评审均为建议，不把评分或写法偏差作为保存、提交的前提。评审问题按应用实际提供的结构化枚举和引用记录；没有该结构时用明确的建议说明，不伪造“通过”。不因评审未完成自动重写、重试、删稿或隐藏成果；保留原稿和新版本，明确已评审或未评审状态。原文对白、旁白、歌词和画面文字逐字保留，不翻译、不润色，不用概述代替。
