# H3 视频提示词

这是本项目编写的 `h3@1` 兼容表达方法。MiniMax 和 H3 仅用于说明目标模型；本包不包含、改写或转授权 MiniMax-H3 仓库中的 Skill 文件。

## 交付给用户的提示词

最终提示词的章节正文使用英文，包括主体定义、摘要、参考保留说明、镜头动作、运镜、环境声与配乐说明。对白、旁白、歌词及画面内可见文字逐字保留原语种。人物称呼在英文说明中保持同一对应，素材编号保持真实绑定。该要求适用于手选通用格式和专用 H3 格式；输入稿或母稿为中文时，在格式适配这一步将说明文字译写成英文。除非用户本次明确指定其它输出语言，按此要求交付。

把用户的话整理成一份能直接交给海螺 H3 的提示词。一句话、散文、分镜稿、纯对白或已排好的稿件都可以作为输入。先认清用户要拍什么、发生顺序、哪些话要原样说。写得清楚的句子直接沿用；已经符合本次格式的段落只调整确有需要的地方。补足格式所需段落，不为了显得更丰富而改变剧情。

区分三种声音意图。原稿指定了音乐，就把指定内容放进配乐段；明确无 BGM，就在该段写“N/A”；完全没提配乐，保留该段并写“未指定”。其余缺少资料的段落同样留出位置。人物出声自语属于镜头内的对白，放在他开口的动作后，再写后续动作。明确是内心活动的内容保留原意，不自行安排人物发声。

## 片段与素材边界

片段从完整剧集或用户当前稿件出发，可以包含一个或多个连续剪辑镜头。镜头只表达片段内部的叙事次序，不要求先创建场次、故事板、静帧或逐镜业务记录。时长、镜头数和参考图数量以用户意图及本次冻结能力为准，不固定秒数，不要求先生成六张或九张图片。

图片是普通素材。人物外观、环境、风格、整片首尾或片内镜头边界等用途来自本次明确绑定；不能根据节点名、图片排列或画面猜测首尾。无参考图的合法输入也能完成内容表达。环境描述不要求一个旧场景实体，也不把环境图当成视频首帧。

本包只提供创作方法，只使用本次实际提供且已获授权的工具，不自行注册或调用其它能力。是否生成图片或视频由本次授权与实际可用工具决定，文字任务只交稿。

## 手选通用输出与专用编译职责

用户手选本方法时不要求视频模型注册 h3@1。profileId=generic 表示应用不会生成H3章节；此时由你在 lines.text 中写出下述章节标签与完整内容，保持外层输出合同不变。明确的多图参考用途可应用 Ref2VA 六段写法；其它输入按实际用途参考基模三段写法，不推断平台支持能力。正文中的来源素材按 references 的 mediaKind 与 ordinalWithinKind 使用 <Picture N>、<Video N>、<Audio N>；内部 referenceUseId 仍按输入原值填写。没有资料的声音章节写“未指定”；明确写了无配乐时使用 N/A。参考用途和事实不明时保留不确定性。

专用 h3@1 编译器下才由程序生成标签。表达风格与格式遵循用户选择，不因目标身份不匹配拒交；真实素材与执行能力校验仍保留。

## 什么时候用

- 冻结目标是 `h3@1` 或用户手选本方法，应用要求把当前冻结的片段视频内容或内容整理产物投影成 H3 兼容提示词。母版只是当前输入的称呼，不是必须先审阅通过的前置。
- `T2VA`、`I2VA`、`FL2VA`、`L2VA` 读取 [references/base-en.txt](references/base-en.txt)。
- `Ref2VA` 还要读取 [references/ref-en.txt](references/ref-en.txt)。

不根据模型名猜测能力；手选方法按上节完成文字表达，专用执行能力以冻结合同为准。



## 官方结构对照

对照 MiniMax-AI/MiniMax-H3 官方 `h3-prompt-writing`（一级来源；本包仍是项目内 h3@1 兼容方法，不复制官方 Skill 原文）：

- 模式名保持 `T2VA` / `I2VA` / `FL2VA` / `L2VA` / `Ref2VA`，与官方一致；模式由冻结输入给出，不从散文猜测。
- 基模字段顺序：`integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`（专用编译器生成标签；generic由模型在text内组织）。
- Ref2VA 六段顺序：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。
- I2VA / FL2VA / L2VA 的首行对齐说明由适配器按官方句式写入；表达时仍从母版事实出发，不把参考图细节 invent 进母版未写的内容。
- 官方建议：具体可见/可听细节优于 “cinematic/beautiful” 空词；对白原语种保留。本仓合同另要求：不因评分/字数拒收，真实回包始终保存。

## 不可改变的内容

- 母版事实、出现顺序、否定极性和镜头关系。
- 台词、歌词与画面文字原文；应用提供的原文不翻译、不润色。
- 已冻结的参考素材用途、编号、首尾帧角色和音频用途。
- 用户明确写出的秒级阶段、总时长和镜头切换位置。

不得为了画面更丰富而增加人物、动作、道具、场景、声音、音乐或镜头。参考素材只用于母版已经声明的身份、外观、空间、动作或声音用途。

## 工作方式

遵守本次实际输出合同。只有请求要求表达行时才按事实和引用关联；只要求正文时不自行造表达行或新业务 JSON。模式资源中的字段在专用模式下由适配器编译，generic手选时写进text，不是额外的JSON属性，也不改变片段初稿合同。

1. 先识别输入模式和应用给出的资源清单。
2. 按母版顺序逐镜头、逐事实表达。第一镜先交代主体和关键动作；后续镜头只在母版确有切换时出现。
3. 把对白和旁白原话完整放到对应动作和时间位置，保留说话人或旁白身份、画内或画外、语气与口型状态。原话可在正文中直接表达；已有对应引文时推荐引用槽位、正文保留语境，避免同一句同时写两份。但没有槽位或对白节点也不能删、改写或只留下“说话”动作。不要靠文本去重改写用户原话。
4. 按目标模式使用参考文件规定的字段顺序。空字段使用应用合同允许的占位值，不自行发明字段。
5. 只返回应用要求的结构，不输出说明、Markdown、备选版本或模型参数。

## 多人对白

五种模式都按 base-en.txt 的「Speakers and voiced lines」写：每句台词通过 quoteIds 挂在开口的那一行；行文结尾写清谁在说、怎么说，第一次开口在来源提供依据时描述稳定的嗓音特征；说话人编号由应用冻结，不改号、不合并、不对调。Ref2VA 另按 ref-en.txt 的「Speakers, pictures and voice-timbre audio」挂说话人参考图、回报音色归属。用正向归属代替长串禁令。

## 动作与交互的表达

只表达母版已有的动作链，稳定区分施动者与对象，保留事件顺序、力度、反应与动作间的空档。不为增强打击感新增招式、伤害、命中结果或音效；没有命中、缺少连续招式或没有声音本身不构成遗漏。表达改进只作非阻断建议，真实事实冲突仍按应用的结构化审阅合同处理。

本节适用于应用已声明的所有 H3 输入模式。动作进入现有详细描述，母版已有的声音意图进入对应音频表达；仍按当前模式读取既有 base/ref 方法资源。不把身份参考图当作首帧，不改首尾帧用途；不新增固定时长、器材词、子弹时间或自然语言时间信息的禁令。

## 写作建议与基本校验

字段顺序、标签、推荐措辞和格式检查用于帮助写作，不是保存或提交的前提。可读取且真实引用正确的表达可以保留为新版本；偏离建议时给出具体提示，不强制改写，不因未命中模板拒收。未完成保真核对时保留原稿与新结果并明确状态，不宣称已核对通过。

## 失败处理

自然语言总时长、约数和事件时间均是合法事实，不是机器时间码。总时长与工作台参数不同或目标不支持某个时长，只给非阻断协调提醒，仍完整表达，不写 conflicts。不能把事件时间当总时长。

遇到保真不确定、写法偏离或字段组织不同，保留原稿与新结果并给具体建议，不因模板或评分拒收。真实素材编号无效、正文不可读取或数据事务不安全时，按应用基本校验明确报告；不假造素材，不静默删除或补写原话，不偷偷切换目标。

## 评审与交付

按本次请求给定的结构和字段闭集返回结果，不另造业务 JSON、编号、错误码或工具。程序只校验必要结构、输入闭集中的真实引用、真实目标能力、权限及数据安全。缺少输入时说明具体缺口，不编造素材、来源或身份，不静默切模型或输入模式。

写作顺序、标签、模板、表达语言建议、画面质量与语义保真评审均为建议，不把评分或写法偏差作为保存、提交的前提。评审问题按应用实际提供的结构化枚举和引用记录；没有该结构时用明确的建议说明，不伪造“通过”。不因评审未完成自动重写、重试、删稿或隐藏成果；保留原稿和新版本，明确已评审或未评审状态。原文对白、旁白、歌词和画面文字逐字保留，不翻译、不润色，不用概述代替。


## 官方标签与手选格式

最终正文使用 H3 标签。将输入中对应图片的 @图N、@ImageN 等编辑标记转换为 <Picture N>，视频使用 <Video N>，音频使用 <Audio N>。N 取该类别中真实冻结的 ordinalWithinKind，不能按出现先后重新排列文件编号。referenceUseIds 属性仍逐字填写内部真实 ID。

Ref2VA 使用 <Subject N> 标识实际引用的人、物或环境，在 subject_definitions 中注明其来自哪个 <Picture N> 或其它来源。Subject 编号独立于图片编号；一张图片可提供多项主体，多张图片也可对应同一主体。只凭原文已确定的对应关系定义，保留简短身份信息。普通身份图在对应 Subject 定义中引用，只有实际帧位或构图锚点才单列 Picture 定义。

summary 从符合实际用途的任务前缀开始，如 [reference generation]。retention_analysis 每个已定义条目一行，采用 ref-en.txt 的关系词。detailed_description 在各主体实际出镜处复用已定义标签，以 [Shot 1] 开始；有切镜时才递增 Shot 编号。开场镜头无时间戳，后续切点按真实时长安排 At MM:SS.mmm，已有精确时间照录。

profileId=generic 时，程序只拼接 text，并为 quoteIds 追加普通引号。为交付 H3 的发声格式，在 text 内完整写说话人 (Sx) 与 <d>[Chinese] 原话</d> 等标签，逐字取自本次母稿引文，该行 quoteIds 留空以避免重复追加。专用 h3@1 则使用 quoteIds，由编译器写发声标签。两种情况下原话都必须完整保留，Sx 沿用已冻结的说话人 ID。无画外音不补画外音，无跨镜或截断不补对应标签。
