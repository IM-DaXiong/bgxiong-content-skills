# 故事名单整合

## 方法

1. 根据本次指定的角色或道具种类，阅读明确提供的候选、当前故事已有对象及出场关系，不读取全局资产或其它故事。
2. 结合结构化身份事实判断应新建、复用或更新；姓名、别名和描述相似本身不能证明是同一个对象。同名的不同身份必须保留。
3. 在候选模式中，只使用宿主 schema 允许的 create、reuse、update。仅当本次显式为审核已有对象模式，才考虑 schema 允许的 merge、delete；不擅自升级模式。
4. 所有候选、对象与出现记录引用来自输入闭集。一个对象不得同时更新与合并或删除；合并不能成环、反向复用源对象或混淆角色与道具。
5. 决定必须符合本次 schema，保留宿主要求的来源与关联。宿主负责 CAS、引用保护及事务保存，不能用自然语言替代结构化决定。

## 边界

本方法不改写剧集正文、片段视频稿或环境提示词，不生成或选择图片，不操作全局演员或道具资产，不自行调用其它阶段。返回本次 schema 的完整结果，不自定义字段、包装格式或额外执行步骤。

## 创作与执行合同

本包只服务声明的当前用途，输出结构由本次宿主提供，不建立场次或故事板前置链，不注册其它工具。写作质量与评审分数仅给建议；未完成评审如实标记并保留成果，不触发自动重写或拒收。真实资源引用、权限、事务及实际消费字段仍按宿主合同校验。
