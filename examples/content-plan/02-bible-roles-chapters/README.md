# 案例 2（中等）：圣经 → 角色 → 剧集

## 这个 Skill 能做什么

给一个**几乎空白**的故事（至少要有故事描述，哪怕很短）一次跑完三件事：

1. **故事圣经**（世界观、基调、不可破的设定）
2. **角色**（从圣经里长出来的人，而不是凭空点名）
3. **剧集**（有了人和设定之后再切集）

它**不会**拆场次、分镜，也**不会**生成定妆图。

相对案例 1：多了 DAG（`dependsOn`）和三层 coverage。相对案例 3：还没有条件分支。

## 为什么必须按这个顺序

Host 按 `dependsOn` 排执行序，**不是**按数组从上到下碰巧成功：

```
bible  ──►  roles  ──►  chapters
```

- `roles` 依赖 `bible`：角色规划吃圣经结果，避免「人设和世界观各说各话」。
- `chapters` 依赖 `roles`：分集时已经知道有谁能上场。

如果你把 `chapters` 的 `dependsOn` 改成只依赖 `bible`、跳过角色，包仍可能通过语法校验，但产品语义就变成「有世界观就能切集、人物后补」——那是另一种 Skill，不要和本案例混为一谈。

`coverage` 必须和三步产出的制品层一致：`bible` / `roles` / `chapters`。多写 `shots` 或少写一层，准备阶段会报 `CONTENT_SKILL_COVERAGE_MISMATCH`（用户侧是人话，日志里才是机码）。

## 怎么做

1. 导入本文件夹（设置 → 创作智能体 → Skills 库 → 导入包）。
2. 打开故事，确认描述栏不是空的（`$ctx.sourceText` 空时，后续 op 会按自己的输入规则失败，**不会**用别的故事凑字）。
3. **生成剧集** → 编排方式选「案例2 · 圣经-角色-剧集」→ 确认。
4. 等 Content Run 跑完：应先后完成圣经、角色、剧集三层规划。

「生成剧集」这个按钮名字只表示**产品入口**，不是「这个 Skill 只能输出剧集」。入口把当前故事交给所选编排；编排自己声明 coverage。

## 跑完你该看到什么

- 圣经、角色、剧集都有规划结果。
- 场次 / 分镜仍空（除非故事里本来就有）。要镜头级，用案例 3。

## 常见改法（学习用）

| 你想要的 | 改法 | 不要做 |
|----------|------|--------|
| 只要圣经+角色，先不拆集 | 删掉 `chapters` 步，coverage 改成 `["bible","roles"]` | 留下 coverage 里的 `chapters` 却删步骤 |
| 有圣经后再拆集、角色另说 | 新 Skill，不要改坏本案例的教学意图 | 同一包里写两套互相矛盾的 dependsOn |
| 顺手定妆 | 当前用户包不能组合 `plan_appearance` / release 下 `plan_image` 不可用 | 写上再指望静默跳过 |

## 这个 Skill 控制 LLM 返回什么格式
本案例偏流程（1.1 仍用 bind，不再使用已删除的 input）。需要控 LLM 返回字段时请用案例 20/21/25/26。

## 字段表（只列本包用到的）
| 字段 | 含义 |
|------|------|
| bind.storyId | 当前故事 |
| bind.sourceText | 故事描述 |

## 你可以改什么 / 不要改什么
可以改 displayName 与步骤顺序。不要写 steps[].input，不要解冻 plan_image。

## 用户怎么用（导入 → 绑定到哪 → 点哪个按钮）
设置导入本文件夹。打开生成剧集或一键直出，编排方式选本 Skill。本包不是场次故事板绑定包。

## 不合格时你会看到什么（人话）
旧 input 包会提示按 1.1 重写。计划验收失败不会偷偷改走内置编排。

## 拷给其它 LLM 时如何改成自己的包（3 步）
1. 复制目录，id 改成 local.你的名字。
2. 按 AUTHORING_SPEC 只改允许字段。
3. 导入后在对应入口选用。
