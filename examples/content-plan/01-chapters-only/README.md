# 案例 1（简单）：只生成剧集

## 这个 Skill 能做什么

打开一个**已经写好故事描述**的故事，跑一遍之后，只产出 **剧集（chapters）** 规划。

它**不会**：

- 写故事圣经 / 角色表
- 拆场次、拆分镜
- 生图、配音、成片包

如果你只想先把长故事切成几集，用这个。

## 包里两份文件各自干什么

| 文件 | 作用 |
|------|------|
| `skill.manifest.json` | 身份证。`id` 必须是 `local.` 开头，否则导入被拒。`displayName` 会出现在设置页和「编排方式」下拉框。 |
| `pipeline.json` | 作业单。这里只有 **一步**：`plan_chapters`。 |

`bind` 里的 `$ctx.storyId` / `$ctx.sourceText` 不是你手填的。用户点「开始生成」时，Host 把**当前故事 id** 和**故事描述全文**注进去。禁止再写已删除的 `steps[].input`。路径解析失败会变成 `null`，后面由该 op 自己校验报错，不会偷偷换成本地默认模型。

## 怎么做（从复制到出内容）

1. 在设置里打开 **创作智能体 → Skills 库**，点 **导入包**，选本文件夹（或把本文件夹打成 zip 再选）。
2. 列表里应出现「案例1 · 只生成剧集」。这只说明包已安装，**还没有改你的故事**。
3. 打开目标故事 → **生成剧集**（或同等入口）。
4. **编排方式**选这个 Skill，不要留「内置规划」。
5. 确认后才会真正跑 `plan_chapters`。失败时软件**不会**悄悄改走内置规划，你会看到人话提示。

## 跑完你该看到什么

- 故事里出现剧集规划（具体落库由 Host 的 Content Run 执行，不是 Skill 自己写 SQLite）。
- 场次 / 分镜列表**不会**因为这个包自动变出来。若要场次，用案例 3 或换一个带 `plan_scenes` 的包。

## 作者改这个案例时注意

- 改 `id` 再导入 = 另一个 Skill；同 id 再导入会提示覆盖。
- 不要加 `plan_appearance` / `plan_image` / `materialize_*`：用户包不允许或当前不可用。
- 改完 `pipeline.json` 后若带着旧的 `pack-pin.json`，校验会对不上；本案例故意不带 pin，导入时 Host 按实际字节生成。

## 这个 Skill 控制 LLM 返回什么格式
本案例偏流程（1.1 仍用 bind，不再使用已删除的 input）。需要控 LLM 返回字段时请用案例 20/21/25/26。

## 字段表（只列本包用到的）
| 字段 | 含义 |
|------|------|
| bind.storyId | 当前故事 |
| bind.sourceText | 故事描述 |

## 你可以改什么 / 不要改什么
可以改 displayName 与步骤顺序。不要写 steps[].input，不要解冻 plan_image。

## 用户怎么用（导入 → 绑定到哪 → 点哪个按钮）
设置导入本文件夹。打开生成剧集或一键直出，编排方式选本 Skill。本包不是场次故事板绑定包。

## 不合格时你会看到什么（人话）
旧 input 包会提示按 1.1 重写。计划验收失败不会偷偷改走内置编排。

## 拷给其它 LLM 时如何改成自己的包（3 步）
1. 复制目录，id 改成 local.你的名字。
2. 按 AUTHORING_SPEC 只改允许字段。
3. 导入后在对应入口选用。
