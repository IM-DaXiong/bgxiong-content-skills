# 案例 3（复杂）：分阶段到分镜（含条件分支）

## 这个 Skill 能做什么

一次编排里做完「能拍之前」的文字规划，并且**按运行时数据决定要不要走到分镜**：

| 步骤 | op | 何时执行 |
|------|-----|----------|
| 1 | `plan_chapters` | 总是（只要准备通过） |
| 2 | `plan_scenes` | 总是，且必须等剧集步完成（`dependsOn`） |
| 3 | `plan_shots` | **仅当**当前故事描述 `$ctx.sourceText` 非空 |

「非空」按 Host 的 `when.notEmpty`：非空字符串、非空数组/对象、`true`、任意数字算通过；`""` / `[]` / `{}` / `null` / 缺失路径算不通过，**该步从本次计划里拿掉**，不是失败装成功。

典型用法：

- 描述写好了 → 剧集 + 场次 + 分镜一条龙（接近「一键直出」要的文字层）。
- 描述还是空的 → 仍规划剧集和场次，**跳过分镜**，避免对着空白正文硬拆镜头。

它**不会**：圣经、角色、生图、成片 `plan_package`。要人设请案例 2；要成片包请另写只含公开 `plan_package` 且前置齐全的包。

## 为什么故意不写 `coverage`

`pipeline.json` 里**没有** `"coverage": [...]`。

原因：准备阶段会按 ** surviving 步骤**（已经过 `when` 过滤）推导制品。若你事先写死 `"coverage": ["chapters","scenes","shots"]`，而描述为空导致 `shots` 被跳过，Host 会判定 coverage 与步骤不一致并硬拒。

规则：

- 步骤永远都会跑齐 → 可以像案例 1/2 那样手写 coverage，且必须与步骤制品完全一致。
- 步骤可能被 `when` 拿掉 → **不要**手写 coverage，让 surviving 步骤推导。

导入时用的是「结构解释」：`when` 只校验语法，**所有步骤都保留**。真正按 `$ctx` 砍步骤发生在 **准备 / 预览**，不是导入瞬间。

## `$ctx` 现在有什么（不要幻想）

v1 准备绑定目前注入：

- `$ctx.storyId`：当前故事
- `$ctx.sourceText`：当前故事描述

`$input.*` 是用户发起参数（本案例未用）。`$snapshot.*` 在规范里存在，但 **WASM 不会在沙箱里解释快照**；声明式 `when` 可以写 `$snapshot.…`，可是准备若没把对应树放进 snapshot，路径就是 `null`，`notEmpty` 为假。本案例只用 `$ctx.sourceText`，避免「写了 snapshot 却从未注入」的假教学。

`when` 只允许恰好一个闭集谓词：`exists` / `notEmpty` / `equals` / `count`。不能写 `and`/`or`，不能写任意 JS。

## 怎么做

1. 导入本文件夹。
2. 打开故事。
3. **想跑到分镜**：先把故事描述写上（任意非空正文），再打开 **生成剧集** 或 **一键直出**，编排方式选「案例3 · 分阶段到分镜」，确认。
4. **想验证跳过分镜**：把描述清空后再准备同一 Skill。预览/准备结果里不应再包含 `plan_shots` 步；剧集和场次仍在。不要指望 UI 把「跳过」显示成成功的分镜层。

失败（缺前置、op 不可用、验收不通过）会明确提示，**不会**改走内置 Native 规划。

## 作者可以怎么改着玩

| 想法 | 合法写法 | 坑 |
|------|----------|-----|
| 有故事 id 才拆场次 | `"when": { "notEmpty": "$ctx.storyId" }` 挂在 `scenes` 上 | 生成入口通常总有 storyId，这步几乎不会跳 |
| 描述等于某个标记才出分镜 | `"when": { "equals": ["$ctx.sourceText", "ONESHOT"] }` | 必须整段描述恰好等于该字符串，对用户不友好 |
| 角色数量恰好 2 才继续 | `"when": { "count": ["$snapshot.roles", 2] }` | 除非准备绑定真的提供 `snapshot.roles`，否则永远跳过 |

改 `when` 后重新导入（同 id 勾选覆盖）。不要手改已生成的 `pack-pin.json` 里的哈希。

## 你可以改什么 / 不要改什么
可以改 displayName 与步骤顺序。不要写 steps[].input，不要解冻 plan_image。

## 用户怎么用（导入 → 绑定到哪 → 点哪个按钮）
设置导入本文件夹。打开生成剧集或一键直出，编排方式选本 Skill。本包不是场次故事板绑定包。

## 不合格时你会看到什么（人话）
旧 input 包会提示按 1.1 重写。计划验收失败不会偷偷改走内置编排。

## 拷给其它 LLM 时如何改成自己的包（3 步）
1. 复制目录，id 改成 local.你的名字。
2. 按 AUTHORING_SPEC 只改允许字段。
3. 导入后在对应入口选用。
