# 动作打斗提示词

状态：`source-approved`。版本：`1.6.0`。工作流：`clips-v1`。包目录：`skills/action-fight-prompt`。

## 用途

从用户的关键动作或旧稿编排连续表演，按观众需要看清的变化重写分镜、节奏和机位，保留事件结果、参考图与明确锁定项。

## 适用场景

正在使用比格熊创作工作台、并选择了上述用途的作者。 声明用途：optimize-segment、clip-video-draft。

## 优化什么

- 从原稿取出必须拍到的事
- 先连动作，再决定从哪里看
- 写成可直接使用的分镜

这些标题来自该包正文的章节，不是另一套执行规则。真正执行以包内 `SKILL.md` 为准。

## 输入

使用当前工作台已经提供的描述、选定素材和冻结参数。布局包还会读取自己的 `references/layout.json`。没有被该包声明的素材不是必需项。

## 输出

- 检查片段连续性或表演问题，并给出仍可执行的修订建议。
- 为单个片段写可独立提交的视频完整稿。

## 可预期效果

1.6.0 经 MiniMax-M3 实测。四动作短稿保住了人物归属及空中结尾，但只返回一句动作概述。14 秒英文稿仍沿用旧切点，并重复第 3 镜，整场重排未通过。仅验证提示词文本。

## 安装与启用

在比格熊中使用目录或 ZIP 导入 `skills/action-fight-prompt`，预览后确认替换。单文件导入会丢掉 references 等附件，带布局的包不要只用单文件。

## 示例

使用「AI 改写提示词」相同的 text.organize 请求格式和最终包正文复测。四动作输入返回甲抬腿踢中、乙抓住甲的腿并将甲甩飞，停在半空，缺少明确取景与节拍。英文原稿在服务端分成 3 块，返回文本重复了 4–6 秒的镜头，保留遮挡视线的第一人称画面，并增加了原稿没有的反击。尚未生成 H3 视频。

1.4.0 使用同一 MiniMax-M3 文本模型和「AI 改写提示词」后端，按本地候选技能正文发起请求。披风三参用例把10秒分成2.5、2、1.5、4秒四个时段，用追逐方向、转身和衣料运动代替手部微操。机位与动作参考覆盖第6秒的绑定不够明确，场地图标签额外重复一次。四动作短稿写出了左右站位，但把被甩方写成主动挣脱腾空，且续写了落地。14秒英文长稿首轮服务返回失败；重试返回的稿保留7个原时间窗、6次硬切、一次第一人称，空间与节奏重排未通过。未据此验收 H3 成片。

1.3.0 的四动作输入兼作教学示例。按两个独立请求实测，第一步归纳出甲抬腿踢中乙的脸、乙抓住甲的腿、甲被甩飞，第二步使用这份原样提要写成新稿，动作归属正确，尾部续写了落地。另测未写入技能的面具追逐场面，面具脱手、红衣人接住、冲进光区和持有者均保留，4秒锁定落在切点，未稳定覆盖该瞬间。文本整理入口没有自动进行两次调用。 同一后端对14秒英文旧稿的一次改写仍沿用7镜6次硬切；另按提取、重写两次调用，第二次照用模型提要，仍发生素材标签错配和擅自改写空中结局，长稿验收未通过。

2026-11-26 使用同一英文稿和相同改写要求验证。1.1.0 的客户端结果为7镜、6次硬切。1.2.0 经同一客户端入口仍分成3块，保住结局但未解决整段节奏。另用整稿与技能正文一次提交给同一模型，得到5镜，开头先露出平台边缘，中段将失衡和擒抱放在同一镜，最后停在人物越过平台的空中。两条路径的消息格式不同。另测8秒中文短稿，返回稿保留第4秒85mm特写与结尾事件。以上均为文字验收，尚未生成视频。

开发对照另测了三种 1.2.1 实验写法。使用同一英文原稿、同一改写要求和文本模型，经客户端相同的后端调用均未达成整场重编。末版仍保留七个原时间窗，并出现被抛人物标签错置。把 62 个来源单元整场提交，保留文本整理的系统消息和输出合同进行对照，七个原时间窗仍被保留。实验稿未替换 1.2.0。记录仅涉及文本返回。
